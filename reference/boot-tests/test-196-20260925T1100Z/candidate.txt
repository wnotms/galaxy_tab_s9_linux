# test-196 candidate — Profile C, `msm.skip_gpu=1`

Status: **candidate ready for physical test.** Not flashed, awaiting explicit
authorization.

## Why this test, and what it does and does not decide

Profile C is the strongest subsystem ablation available as a command-line token.
It removes the Adreno driver registration entirely, and with it the GMU, the
AOSS/ACD path, the GPU power domains and the GPU's RPMh and interconnect votes -
while leaving DPU, DSI and the panel console working, because
`adreno_register()` sits beside the display registrations in `msm_drm_register()`
and `msm.separate_gpu_kms=1` already puts the GPU on its own DRM device.

**The parameter is `msm.skip_gpu=1`, not `msm.no_gpu=1`.** `MODULE_PARM_DESC(no_gpu,
...)` only attaches a description string; `module_param(skip_gpu, bool, 0400)`
registers the name. The old profile used the description name, which the kernel
ignores silently, so any earlier "no-gpu" result would have been a false negative.
Verified on the device: `/sys/module/msm/parameters/skip_gpu` exists and
`no_gpu` does not.

**What a clean result means.** Record it as `not reproduced in N rounds` - and nothing more.
Five, or even twenty, clean rounds cannot exclude a ~3-7 % event; 22 clean baseline
cycles were already recorded this session. It is *not* "GPU excluded".

**What a wedge means.** A genuine CPU-level wedge bound to the round - soft lockup,
RCU stall, hung_task, workqueue lockup, unanswered NMI or panic, or an unrequested
restart - downgrades the GPU/GMU/ACD path decisively. Stop, preserve, do not round
on to fill a series.

## The gate: prove the ablation took, before trusting any round

Run after the first C boot, and record the output in this directory:

```
# 1. the parameter exists under its REAL name
cat /sys/module/msm/parameters/skip_gpu          # expect Y

# 2. the command line actually carries it
tr ' ' '\n' < /proc/cmdline | grep '^msm.skip_gpu=1$'

# 3. the whole point: the GPU really is unbound
basename "$(readlink -f /sys/bus/platform/devices/3d00000.gpu/driver)"   # expect empty/NONE

# 4. and the display survived the ablation
cat /sys/class/drm/card*-DSI-1/status            # expect connected
ls /sys/class/drm/                               # DPU/DSI devices still present
```

If (3) still shows `adreno`, the profile did not take and **the round is
`unattributed`** - not a clean result.

## Evidence each round must carry

The harness now produces all of this per round, and `verdict=wedge` copies it into
`wedge-round-N/` automatically:

* `identity=GTS9_AB run/profile/round/boot_id`, stamped into `/dev/kmsg` and
  `/dev/pmsg0` before the reboot and read back from the next boot - so console,
  journal, pstore and USB trace are one round by construction;
* `verdict` in `clean | wedge | suspect | unattributed`;
* `wedge_markers` and `suspect_markers`, counted per kernel channel
  (`_klog`, `_pstore`);
* `presence_outages` / `automatic_reboot` / the second outage's timestamps, from
  the USB presence trace - the detector that was silently broken until test-195;
* the tablet's own `console-ramoops-0` and pmsg, copied verbatim.

## Failure criteria

Stop the series immediately, and treat the run as a **finding** rather than a
result to average, on any of: `verdict=wedge`; a second USB outage; or a `stall-ab`
probe that reports the tablet never came back. Preserve, then report.
