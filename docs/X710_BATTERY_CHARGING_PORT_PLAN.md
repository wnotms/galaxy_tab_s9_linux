Audit date: 2026-09-28. Target: `origin/test` at `aaba6faa0b82fb6ec4a6010b8b83c0e91b035f57`, pinned Linux `v7.2-rc3` (`a13c140c...`). Same-model reference: `nacht20-de/gts9wifi-fedora-linux` at `ab123e7d1dbc0cbcd35661f9761197e977b15aa9` (its current `main`/HEAD when audited), checked against the local clone and [upstream repository](https://github.com/nacht20-de/gts9wifi-fedora-linux/tree/ab123e7d1dbc0cbcd35661f9761197e977b15aa9). The Samsung GPL source inspected locally is `/home/ms/Samsung/kernel_platform/msm-kernel`; its X710 board file is `arch/arm64/boot/dts/samsung/galaxytab/gts9wifi/gts9wifi_eur_open_w00_r02.dts`. This is a source and build audit, **not** evidence that our tablet charges under Linux.

## Current gap and architecture

The current production DTS describes `simple-battery`, the SM5714 charger at I2C address `0x49`, external pack thermistor, the SM5714 USB-PD controller at `0x33`, the SM5440 pump at `0x63`, Type-C connector graph and portions of PS5169 wiring. The production kernel has **no binding SM5714 charger/fuel-gauge or TCPC driver**. `CONFIG_POWER_SUPPLY=y`, `CONFIG_TYPEC=y`, `CONFIG_TYPEC_TCPM=y` and `CONFIG_USB_ROLE_SWITCH=y` are present in the Test249 resolved config, but these generic frameworks do not create `sm5714-battery` or `sm5714-usb`. The current DTS and source have no dependence on dynamic `i2c-X` numbers; retain DT controller/address based matching.

The same-model port drives the SM5714 directly over I2C because the Samsung ADSP firmware does not expose the `charger_pd` path expected by `qcom_battmgr`. Its `kernel/files/sm5714_battery.c` binds `siliconmitus,sm5714` and claims companion gauge `0x71` and MUIC `0x25` on the *same adapter*. `sm5714_usbpd.c` binds the separate `0x33` TCPC and delegates PD policy to TCPM. `sm5440_direct.c` controls the `0x63` pump and requests PPS. Do not import Qualcomm battmgr or Samsung's vendor USB-PD policy engine without new firmware evidence.

## Driver review

| Same-model file | Provenance and content | Linux 7.2-rc3 integration | Stage 1 decision |
| --- | --- | --- | --- |
| `sm5714_battery.c` (1349 lines) | New GPL-licensed mainline-style X710 AP-direct driver. Register addresses, charger BATREG/current encoding and fuel-gauge SRAM fixed-point conversions derive from Samsung GPL `sm5714_charger.c`, `sm5714_fuelgauge.c` and MUIC source. The polling, charger state restoration, pack-thermistor IIO use, `power_supply` registration and 4.44 V float re-arm are same-model port logic, not a wholesale Samsung driver. It also contains later fast-charge UI, direct-charge handoff, OTG and TCPM callbacks. | Current APIs (`devm_i2c_new_dummy_device`, `devm_power_supply_register`, `power_supply_get_battery_info`, IIO consumer) are present in the pinned tree. | `sm5714_usbpd.c` (910 lines) | Same-model TCPC transport using regmap/IRQ plus TCPM; references charger callbacks for PD limits and OTG. Workarounds include level-low IRQ drain and CC attach rechecks. | Needs `TYPEC_TCPM`, Kconfig/Makefile hook and review of callback signatures in 7.2-rc3. | `sm5440_direct.c` (937 lines) | Same-model PPS charge-pump policy, Samsung GPL register sequence, thermal/fault/ADC handling, battery handoff and retries. | Depends on SM5714 + TCPM/PPS and explicit parameter review. | **Not copied, built, probed or enabled in Stage 1.** Stage 3 opt-in only. |

The SM5714 SRAM window is `RADDR=0x8c`, `RDATA=0x8d`; SOC SRAM word `0x00` is unsigned Q8.8 (`25600` means 100%). Voltage/current/temperature conversions must preserve the stock/source formulas, with the current sign verified on the actual tablet before any charging claim. A compile pass cannot verify those measurements.

## DTS node audit

| Node/function | Current tree versus same-model tree | Classification and action |
| --- | --- | --- |
| `battery: simple-battery` | Present in both; current design capacity `8160000 µAh`, max `4440000 µV`, min `3400000 µV`. | Samsung's [official SM-X710 specification](https://www.samsung.com/pt/tablets/galaxy-tab-s/galaxy-tab-s9-wi-fi-graphite-128gb-sm-x710nzaaeub/) calls **8400 mAh typical** and **8160 mAh rated minimum**. The existing design value matches the rated minimum; **do not change it** in this candidate. The available Samsung GPL board-file discrepancy is recorded below. |
| SM5714 charger `0x49` | `&i2c_hub_8/charger@49` already has compatible, `monitored-battery` and external `battery-temp` IIO channel. | Already suitable for Stage 1 binding. Add only the out-of-tree driver; do not change Linux dynamic bus numbers. |
| SM5714 fuel gauge `0x71`, MUIC `0x25` | Current and reference DTS omit separate children; reference driver creates dummy I2C clients from charger probe. | Different but intentional. Do not add duplicate DT clients that would conflict with dummy claims. |
| External pack thermistor | Current PMK8550 ADC5 Gen3 `0x144` IIO channel, labeled `battery-thermistor`; reference has equivalent wiring. Upstream ADC5 Gen3 declares AMUX1 100k thermistor as `IIO_TEMP` with processed reading. | Already equivalent. For charge safety, an absent/invalid read must inhibit charging, not fall back to fuel-gauge die temperature. |
| SM5714 USB-PD `0x33` / connector | Current `&i2c_hub_9/usbpd@33` has IRQ GPIO133, pinctrl, connector PDOs, endpoints; reference has TCPC provider. | Driver missing, **Stage 2**. Do not bind it in Stage 1. Fixed PDO caps and 9 V/3 A budget are not a request to raise actual charge current. |
| Type-C mux, PS5169, USB role | Partial graph and mux nodes exist; current `&usb_1` is forced peripheral to preserve ADB/NCM. Reference has more role/mux/DP support. | Needs verification in Stage 2; unsafe to copy wholesale. Do not change gadget/role/PS5169 in Stage 1. |
| SM5440 `0x63` | Node exists under `&i2c_hub_3`, with GPI DMA on this SSC-visible bus. No driver. | Different but intentional: descriptive node only. **Stage 3** driver must stay absent in Stage 1. Do not change its bus/power settings. |

The current `docs/FEDORA_KERNEL_DIFF.md` covers broader differences. This plan supersedes none of its unrelated display, USB or kernel findings. Neither tree's host `i2c-X` numbering is a stable binding.

## Stock evidence, limits and conflicts

| Parameter | X710 Samsung GPL source | Same-model port / current candidate |
| --- | --- | --- |
| Float voltage | `gts9wifi_eur_open_w00_r02.dts:548`: `battery,chg_float_voltage=<0x1158>` = **4440 mV**. `sm5714_charger.c:195-220` maps 4.05–4.62 V in 10 mV steps to `CHGCNTL4[5:0]` (register `0x1a`). | Current DTS `4440000 µV`. Same-model driver programs BATREG at probe and every ordinary reconfiguration because charger power-cycle can lose it; this is required in Stage 1. Never raise it for UI 100%. |
| Design capacity | The available r02 Samsung GPL DTS says `battery,battery_full_capacity=<0x2648>` = **9800** (unit and applicability in vendor policy require confirmation). Samsung's [official SM-X710 specification](https://www.samsung.com/pt/tablets/galaxy-tab-s/galaxy-tab-s9-wi-fi-graphite-128gb-sm-x710nzaaeub/) instead states **8400 mAh typical / 8160 mAh rated minimum**. | Current production `simple-battery` says **8160 mAh**, matching the official rated minimum, and labels EB-BX916ABY. The GPL `0x2648` is inconsistent with the official SM-X710 capacity and must not override the verified product specification. Preserve production `8160000 µAh`; reconcile the GPL value only with pack-specific evidence later. |
| Charging/current | Samsung `sm5714_charger.c:249-284` encodes input current as `(mA-100)/25`, fast current from 109.375 mA in 15.625 mA steps. X710 board DTS carries several per-cable/thermal limits, which are context dependent. | Same-model ordinary path uses SDP 500/500 mA, CDP 1500/1500 mA, DCP 1800 mA input / 2100 mA battery, and a 15 W 9 V PD default. Stage 1 has no TCPM contract, so may only apply the bounded BC1.2 cases; unknown USB stays at 500 mA. Do not infer 3 A entitlement from the connector PDO. |
| Thermal | Samsung board DTS uses the external pack thermistor and includes warm/overheat policy; example r02 `battery,wire_warm_overheat_thresh=<0x1f4>` = 50.0 °C and `battery,wire_normal_warm_thresh=<0x1a4>` = 42.0 °C. | Same-model driver uses 46 °C reduced-current and 50 °C stop, returning to normal below 42 °C. Stage 1 must fail closed if the pack IIO channel is unavailable/implausible; do not substitute SM5714 die temperature as the charge safety input. |
| Bus/address | Samsung X710 board DTS has SM5714 MFD `0x49`, USBPD `0x33`, SM5440 `0x63`, with gauge/MUIC under MFD; current/reference board DTS map the charger family to `&i2c_hub_8`, PD to `&i2c_hub_9`, pump to `&i2c_hub_3`. | Bind by controller/node/address, never by `/dev/i2c-X` number. |

Samsung's full vendor battery policy also applies cable, ageing and other protections that the small Stage 1 mainline driver does not reproduce. The first hardware run must explicitly verify temperature, current sign, charge state and absence of warnings before calling charging functional.

## Kconfig and build gates

Test249 resolved config (`out/kernel-no-dcc-production/config`) has `CONFIG_POWER_SUPPLY=y`, `CONFIG_IIO=y`, `CONFIG_TYPEC=y`, `CONFIG_TYPEC_TCPM=y`, `CONFIG_USB_ROLE_SWITCH=y`, and `# CONFIG_HVC_DCC is not set`. It has no `BATTERY_SM5714`, `TYPEC_SM5714` or `CHARGER_SM5440_DIRECT` because Kconfig definitions are missing. The same-model `prepare.sh` defines `BATTERY_SM5714` with `depends on I2C && IIO`, `TYPEC_SM5714` with `depends on I2C && TYPEC_TCPM && BATTERY_SM5714`, and `CHARGER_SM5440_DIRECT` with `depends on I2C && BATTERY_SM5714`. Stage 1 adds **only** `CONFIG_BATTERY_SM5714=y` and its Kbuild hook. Stage 2 may add TCPC/TCPM transport. Stage 3 may add direct charger, default and runtime OFF. The resolved `.config`, not just the fragment, is the gate.

The expected Stage 1 config delta is `CONFIG_BATTERY_SM5714=y` and any narrowly justified dependency resolution only. `CONFIG_HVC_DCC=n` and all Test249/250 CPU diagnostic exclusions must remain. Compare exact old/new resolved configs; any unexpected delta forbids hardware testing. Build kernel **and** modules, DTB, DT validation available in this tree, depmod and provider audit. No flash during candidate preparation.

## Stages, risks, acceptance and rollback

| Stage | Minimum patch set and risk | Acceptance and rollback |
| --- | --- | --- |
| 0: audit | This document only. Risk is misreading same-model measurements as our machine's data. | Verify source pins, stock figures, dependency map and production baseline; rollback is reverting this document. |
| 1: battery and ordinary charger | Port reviewed SM5714 power-supply driver, a Kconfig/Makefile hook and `CONFIG_BATTERY_SM5714=y`; use existing charger/thermistor DT node unless a build proves a missing binding. No direct/PPS/OTG/UI controls or USB role change. Risks: wrong temperature scaling, register/current encoding, charger retained state, false charge status and loss of rescue transport. | First pass: resolved config, full kernel/modules/DTB/dtbs_check where available, depmod, provider audit, host tests, config/DTS diff and registered candidate. Stop **before flashing**. Later user-authorized physical check: battery-only `present=1`, Discharging, plausible SOC/V/I/temp; insert ordinary charger, USB online, Charging, actual pack current sign and SOC trend for 10–20 min, normal temperature and no I2C/watchdog/kernel/ADB/NCM regression; unplug returns Discharging. Roll back only with the preserved matched Test249 boot/vendor_boot + module set via verified recovery procedure if a later test fails. |
| 2: SM5714 TCPC/TCPM | Separate `sm5714_usbpd.c`, Kconfig hook, inspect connector/role wiring without copy-pasting PS5169/DP changes. Risks: Code43, ADB/NCM loss, wrong PD contract/role. | Only after Stage 1 hardware acceptance. Exercise attach/detach, both orientations, standard Type-C and PD, USB peripheral/ADB/NCM and no new enumeration faults. Roll back matched Stage 1 image/modules; stop on first USB regression. |
| 3: optional SM5440 PPS | Separate `sm5440_direct.c`, guarded Kconfig, pump OFF by default, stock-verified limits and fault/temperature recording. Risks: pack overvoltage/current, thermal shutdown, reverse blocking, VBUS/IBUS faults. | Only after Stage 1 and 2 acceptance. First prove the OFF state, then bounded opt-in testing with V/I/temp/SOC/PD logs and stop on any protection trip. Roll back matched Stage 2 image/modules and leave pump OFF. No Stage 3 code or test is part of the present candidate. |

The source port's ~15 W switching and ~23 W PPS measurements are sanity references, not acceptance results or a reason to increase this device's limits. The battery-only and plug/unplug sequence requires user-authorized device handling; this work ends at a buildable, unflashed Stage 1 candidate.
